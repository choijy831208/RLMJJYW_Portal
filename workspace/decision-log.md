# Decision Log

## 2026-04-27

### 추가 포털 결정

Planning Agent는 가족포털의 기본 4개 포털 외에 책임과 완료 상태를 다루는 포털이 필요하다고 판단했다.

Development Agent는 스케줄 포털과 할일 포털의 데이터 모델이 분리되는 편이 구현과 유지보수에 유리하다고 판단했다.

Verification Agent는 스케줄이 날짜 중심이고 할일이 상태 중심이므로 검증 기준도 분리되는 편이 명확하다고 판단했다.

결정:

- `가족 할일 포털`을 추가한다.

### 뉴스 포털 방식

외부 API 없이 로컬 뉴스 클립 저장 방식으로 구현한다.

이유:

- HTML 파일만으로 실행되어야 한다.
- 네트워크나 API 키가 없어도 동작해야 한다.
- 가족에게 중요한 뉴스를 직접 선별하고 메모할 수 있어야 한다.

## 2026-04-28

### 로그인 방식 변경

Planning Agent는 가족포털이 가족 단위 공간이므로 구성원 이름만으로 들어가는 방식보다 가족 코드와 비밀번호를 필수로 두는 편이 낫다고 판단했다.

Development Agent는 서버 없이 실행해야 하므로 브라우저 `localStorage`에 가족 코드와 비밀번호 해시를 저장하는 방식을 제안했다.

Verification Agent는 로컬 해시가 서버 인증을 대체하지는 못하지만, 같은 브라우저 안에서 실수로 포털이 열리는 문제를 줄일 수 있다고 판단했다.

결정:

- 로그인 필수값은 `가족 코드`와 `비밀번호`로 한다.
- `구성원 이름`은 인증값이 아니라 표시 이름으로 사용한다.
- 비밀번호 원문은 저장하지 않고 로컬 해시만 저장한다.

### 모바일 최적화

Planning Agent는 가족포털이 반복적으로 확인하는 생활형 앱이므로 핸드폰 접근성을 우선해야 한다고 판단했다.

Development Agent는 기존 상단 메뉴보다 하단 고정 탭이 엄지손가락 접근성과 화면 효율 면에서 낫다고 판단했다.

Verification Agent는 하단 탭이 콘텐츠를 가리지 않도록 안전영역과 하단 패딩을 함께 적용해야 한다고 판단했다.

결정:

- 모바일에서는 포털 메뉴를 하단 고정 탭으로 표시한다.
- `viewport-fit=cover`와 `env(safe-area-inset-*)`를 사용해 기기 안전영역을 보정한다.
- 모바일 입력창은 16px 이상으로 유지해 자동 확대를 줄인다.
